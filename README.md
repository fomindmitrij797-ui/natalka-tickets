# Натальная карта — бесплатные уведомления в Telegram через GitHub Actions

Бот выполняет **одну проверку по расписанию GitHub**, не работает фоновым процессом. Ищет новую ссылку на будущую съёмку и признаки того, что билеты вернулись после распродажи. Статус в форме Intickets определяется приблизительно; нет гарантии, что свободные места будут найдены.

## Что делать

1. Создайте **публичный** репозиторий GitHub, например `natalka-tickets`. Публичный обязателен для неограниченного бесплатного стандартного GitHub Actions; для private расходуются включённые минуты.
2. Распакуйте этот ZIP. В репозитории нажмите `Add file` → `Upload files`. Загрузите `check.py`, `requirements.txt`, `state.json`, `README.md`. Важно: файл `.github/workflows/check-tickets.yml` должен остаться **именно по этому пути**. GitHub веб-интерфейс может не загрузить пустые или скрытые папки при перетаскивании: проще создать workflow вручную: `Add file` → `Create new file`, в поле имени ввести `.github/workflows/check-tickets.yml`, скопировать содержимое из архива и сохранить (Commit changes).
3. В Telegram откройте вашего бота, отправьте `/start` (он пока не ответит — это нормально).
4. Узнайте **числовой chat ID** своего Telegram (например, можно написать `/start` боту @userinfobot, если доверяете этому сервису; или открыть `https://api.telegram.org/botВАШ_ТОКЕН/getUpdates` у себя в браузере после `/start` вашему боту, найти `"chat":{"id":12345...}`). **Не публикуйте токен в GitHub или в чат.**
5. GitHub → Settings → Secrets and variables → Actions → New repository secret. Создайте два секрета: `TELEGRAM_BOT_TOKEN` (токен из BotFather) и `TELEGRAM_CHAT_ID` (только числовой ID).
6. GitHub → Settings → Actions → General → Workflow permissions → **Read and write permissions** → Save. Нужно, чтобы бот мог сохранять `state.json` между проверками.
7. GitHub → Actions → `Check Natalka tickets` → `Run workflow`. После запуска проверьте лог. Если обнаружена новая ссылка на будущую съёмку, сообщение придёт в Telegram. Если сейчас будущих съёмок нет, сообщений пока не будет: это нормально.

## Частота и ограничения

- Расписание: **примерно каждые 5 минут** (`2-59/5 * * * *`), без гарантии точного времени. GitHub может задерживать или пропускать запуски.
- На **публичном репозитории стандартные GitHub-hosted runners бесплатны**. Код и файл `state.json` публичные; токен и chat ID хранятся в GitHub Secrets, не в файлах.
- Workflow автоматически отключается после 60 дней без активности в публичном репозитории. Этот бот делает коммиты при успешных проверках, но всё равно периодически проверяйте вкладку Actions.
- Отдельные страницы продажи могут измениться или блокировать автоматический браузер: если логи показывают `unknown`, наличие не подтверждено.
- Уведомление о новых ссылках может прийти даже до фактического появления свободных мест; при возврате мест сообщение содержит слово «возможно».
- Никогда не выкладывайте свой токен и не покупайте билеты у перекупщиков.
